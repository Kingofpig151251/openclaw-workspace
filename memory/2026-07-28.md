## 郵件同步修復 ✅

### 問題
- cron 跑 mail-sync.py 持續報錯，累計 36+ 次失敗
- 第一階段錯誤：`node: No such file or directory`（exit 127）— PATH 已有但 HOME 缺失
- 第二階段錯誤：`Authorization required`（exit 3）— agently-cli 找不到 OAuth 憑證
- 第三階段錯誤：`PermissionError: Permission denied` — maildir 目錄權限問題

### 根因
1. crontab 缺 `HOME` 環境變量 → agently-cli 找不到 `~/.agently-cli/config.json` 和 `~/.local/share/agently-cli/bootstrap_token.enc`
2. trim.openclaw 用戶不在 Administrators 群組 → 無法寫入 maildir（目錄 owner 是 lam151251:Administrators，權限 775）
3. cron 的 `chown -R 1000:1000` 會把權限改回 lam151251，導致下一輪 trim.openclaw 又不能寫

### 修復
1. crontab 加 `HOME=/vol1/@apphome/trim.openclaw/data/home`
2. `usermod -aG Administrators trim.openclaw` — 加入群組
3. cron 改用 `sg Administrators -c "python3 mail-sync.py"` 啟用群組
4. cron 加 `sudo chmod -R g+w maildir/` 確保群組可寫
5. 最終 crontab：
   ```
   HOME=/vol1/@apphome/trim.openclaw/data/home
   PATH=/vol1/@appcenter/nodejs_v24/bin:/usr/local/bin:/usr/bin:/bin
   */5 * * * * cd /vol1/@apphome/mail-archive && sg Administrators -c "python3 mail-sync.py >> sync.log 2>&1" && sudo chown -R 1000:1000 /vol1/@apphome/mail-archive/maildir/ && sudo chmod -R g+w /vol1/@apphome/mail-archive/maildir/
   ```

### 測試
- 手動跑成功：`Inbox: +1 synced, -1 remote deleted`，拉到 GitHub 2FA 要求信
- cron 每5分鐘自動跑，下次驗證看 sync.log

### 教訓
- cron 環境變量極度精簡，PATH 和 HOME 都要手動設
- 用戶群組變更不影響已運行的進程，需 `sg` 或新 session
- `chown` 會覆蓋群組寫權限，需配套 `chmod -R g+w`

## Hermes 清理 ✅

### 背景
- 小king 已移除 hermes 應用，要求清理殘留

### 發現的殘留
1. `hermes-restart.service` — systemd 殘影（service 文件已刪，只剩 failed 狀態）
2. 系統用戶 `trim.hermes` — 還在 /etc/passwd
3. `/var/lib/systemd/linger/trim.hermes` — linger 殘留
4. `/vol1/@apphome/trim.hermes` — home 目錄
5. `/tmp/hermes-*` — 大量臨時文件（100+）
6. `/var/log/apps/trim.hermes.log` — 日誌
7. trim.hermes 用戶的 systemd user session 進程還在跑

### 清理操作
1. 先殺掉 trim.hermes 的 user session 進程
2. `systemctl reset-failed hermes-restart.service` — 清除 systemd 殘影
3. `sudo userdel trim.hermes` — 刪除系統用戶
4. `sudo rm -rf /vol1/@apphome/trim.hermes` — 刪除 home 目錄
5. `sudo rm -f /var/lib/systemd/linger/trim.hermes` — 刪除 linger
6. `sudo rm -f /var/log/apps/trim.hermes.log` — 刪除日誌
7. `sudo rm -rf /tmp/hermes-*` — 清理臨時文件

### 教訓
- shell 命令預期可能無結果時加 `|| true`，避免 runtime 誤報 `⚠️ 🛠️ Exec failed`
- 小king 不喜歡看到這種誤報訊息，之後一律避免
