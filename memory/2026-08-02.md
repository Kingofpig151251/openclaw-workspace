### 郵件分類同步修復

#### 問題
- 本地分類（Dovecot IMAP）不會同步回 Gmail
- mbsync 的 `Create Both` + `Flatten .` 在 Gmail 端建出重複標籤（`/Jobs`、`Jobs`、`_School` 等）
- Maildir 格式用 `.資料夾名` 表示子資料夾，`Flatten .` 把點解析成路徑分隔符，在 Gmail 建出帶底線的標籤

#### 修復
- **classify.py 重寫**：改為直連 Gmail IMAP 操作（加標籤 + 從 INBOX 移除），不再本地操作
- **mbsync 配置**：`Create Both` → `Create Near`（只本地建資料夾，不在 Gmail 端建）
- **Gmail 端清理**：刪除所有重複/帶底線的標籤（_Drafts, _Sent, _Spam, _Trash, /Jobs, /Finance 等）
- 最終 Gmail 標籤只剩 5 個：School, Finance, Jobs, System, Promotions
- 分類結果：School 12 / Finance 4 / Jobs 3 / System 1 / Promotions 1 / INBOX 0

#### sync.sh 優化
- 加了進程鎖（LOCKFILE），防止重複執行
- 重啟時 OpenClaw 報錯 "Refusing to signal PID" 是因為 mbsync 子進程不被認得，不影響功能

### 模型配置更新

- 該模型超時不可用，已廢棄

#### 訊飛高效版完整模型清單匯入
- 19 個模型全部加入 openclaw.json 和 models.json
- 抵扣係數：×5(xopglm52, xopdeepseekv4pro, xopkimi27code) / ×4(xopglm51, xopkimik26) / ×3(xopglm5, xopkimik25) / ×2(auto, xsparkx2agent, xsparkx2, xopdeepseekv4flash, xopdeepseekv32, xminimaxm25, xopqwen35397b) / ×1(xsparkx2flash, xopqwen36v35b, xopqwen35v35b, xop3qwencodernext, xopglmv47flash)

#### 主力模型切換
- xopglm52 → xopglm51（GLM-5.2 → GLM-5.1）
- 原因：GLM-5.2 限流嚴重
- 抵扣從 ×5 降到 ×4，省 20% 額度

### Timeout 配置調整
- `agents.defaults.timeoutSeconds`: 900 → 1800（15 分鐘 → 30 分鐘）
- 原因：長任務（OCR、多步驟操作）容易超時
- 討論結論：
  - timeout 只是「等多久才放棄」，不是「等多久就能成功」
  - 限流問題靠加第二 provider 解決，不是靠加大 timeout
  - 但小king決定不加第二 provider（GLM-5.1 才夠用）
  - 5 分鐘太短（正常任務也會超時），30 分鐘合理
  - 真正掛了 30 分鐘後放棄也合理

### LLM 超時機制研究
- 兩層超時：Provider timeout（HTTP 請求層）+ Agent timeout（整個 turn 上限）
- Provider timeout 不能超過 Agent timeout
- 超時觸發 failover：timeout-shaped error → 嘗試 fallback 模型
- Cooldown：1st 30s / 2nd 1min / 3rd+ 5min（上限）
- 每 5 分鐘自動 probe primary，恢復了切回
- 限流（429、concurrency limit 等）也觸發 cooldown + failover
- 但目前 fallback `auto` 也是訊飛，限流時沒有真正的備選

### xopglm51 contextWindow

- GLM-5.1 實際 context 上限不確定
- 建議先維持 128k，觀察幾天：頻繁 compaction → 調大，input too long → 調小

## 下午工作（~17:00）

### fitness-coach-app: recurringGroupId Bug 修復

#### 問題
- 用戶報告 JS 錯誤：`Uncaught ReferenceError: recurringGroupId is not defined`
- AI chat 出現「查看系列」按鈕，但 app 根本沒有系列功能
- Docker 容器裡的 JS 是舊的（`index-UPqFWw3X.js`），多次 `--no-cache` rebuild 都沒更新

#### 根因分析
- Vite minifier 把 `const recurringGroupId = btn.dataset.recurringGroupId; switch(actionType)` 壓成 `switch(e.dataset.recurringGroupId,t)` — 逗號表達式導致 `recurringGroupId` 變成未定義變量
- 更根本的問題：`view-series` action 根本不該存在，app 沒有系列功能

#### 修復
- 移除 `_handleResultAction` 裡 `view-series` case
- 移除 `_sanitizeAction` 裡 `recurringGroupId` 白名單
- 移除 `_renderResultCard` 裡 `data-recurring-group-id` 屬性渲染
- 重新 Vite build → hash 終於變了：`index-UPqFWw3X.js` → `index-C4_nfdAm.js`
- Docker 容器重建部署成功

#### 教訓
- Vite content hash 基於文件內容，如果 minified 結果剛好 hash 一樣，`--no-cache` 也沒用
- 需要確認 build 產物內容是否真的改變，不能只看 hash
- 移除不存在功能的代碼比修復它更正確
